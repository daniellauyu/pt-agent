# PT Agent

PT 站点 Free 资源的自动下载工具：**只下载值得下的**，并在 Free 到期前清掉下不完的任务。

提供两个版本，功能定位不同，但**共享同一套决策逻辑**：

- **[Chrome 插件](#一chrome-插件)** —— 装在浏览器里，你点一下它扫一次，自己过目再决定
- **[终端守护进程](#二终端守护进程)** —— 跑在 NAS / 服务器上，按随机间隔自动扫描并下载，不需要浏览器

## 它解决什么问题

PT 站的 Free 资源有时限。手动盯着抢很累，无脑全下又会出事——**下不完的任务过了 Free 期
会真实计入下载量**，分享率被拉低，还可能触发 HR。

所以这个工具做两件事：

1. **只推送「推荐」级别的资源**。按 Free 剩余时长、做种/下载比、体积、HR 标记等算分，
   再过一遍本地安全准入。两关都过才发送到下载器。
2. **入队时把 Free 截止时间写进下载器标签**，到期前自动删掉还没下完的任务（含文件）。

## 该选哪个版本

| | Chrome 插件 | 终端守护进程 |
|---|---|---|
| **触发方式** | 手动点「扫描」 | 随机间隔自动跑（默认 40–90 分钟，可配） |
| **需要浏览器** | 需要，且 Chrome 得开着 | 不需要 |
| **运行位置** | 你的电脑 | NAS、软路由、小主机、云服务器 |
| **界面** | 插件弹窗 / 全屏工作台 | 同款视觉的 WebUI（默认 `127.0.0.1:7788`） |
| **决策与下载** | 完全一致 | 完全一致 |
| **Free 到期删除** | 默认**关闭**，需手动开启 | 默认**开启** |
| **种子文件抓取** | 受同源策略限制，CDN 302 后常拿不到字节，只能退化成让下载器自己抓 | 无同源策略，永远能拿到字节再上传，成功率更高 |
| **配置存储** | `chrome.storage.local` | `~/.ptagent/config.json` + `.env` |
| **适合** | 想自己过一眼再决定，或先熟悉它的判断标准 | 无人值守，24 小时不错过 Free |

**两个可以同时用**：插件的配置能一键导出，守护进程一条命令导入。
只是它们各自独立管理自己的任务，不共享运行状态。

## 一、Chrome 插件

装在浏览器里的手动版。适合先熟悉它的判断标准，或者你本来就习惯自己过一眼再决定。

### 安装

1. Chrome 打开 `chrome://extensions/`
2. 开启右上角**开发者模式**
3. 点「加载已解压的扩展程序」，选择本仓库的 `pt-agent-extension/` 目录

无需编译，无需 npm install。

### 配置

点插件图标 → **设置**，两块分开配置：

**下载器**（支持多台）

| 字段 | 说明 |
|---|---|
| 地址 | 如 `http://192.168.1.10:8080/` |
| 账号 / 密码 | qBittorrent WebUI 的登录凭据 |
| 保存目录 | 留空则用下载器默认 |
| 分类 | 默认 `PT_AGENT`，首次发送时自动创建 |

**列表顺序就是探测优先级**。把内网地址放前面、公网放后面，插件每次会按顺序探一遍，
连得上的第一台就用它——在家走内网，出门自动切公网，不需要手动改配置。

主机权限在运行时按需申请，改地址不用改 `manifest.json`。

**站点**

填 M-Team 的 API Key（站点 **控制台 → 实验室 → 存取令牌** 生成）。
站点地址和 API 地址已内置默认值。

### 使用

**不需要先打开 M-Team 页面。** 点插件图标就会通过 API 拉取账号信息和多页 Free 资源。

界面分四个菜单：

| 菜单 | 内容 |
|---|---|
| **种子决策** | 扫描结果，按推荐 / 风险 / 拒绝分栏，每行显示评分、体积、做种比、Free 剩余和截止时间 |
| **下载中** | 下载器当前任务、进度、速度，以及从标签读出的 Free 截止时间和保护状态 |
| **设置** | 下载器、站点、下载策略、Free 保护 |
| **日志** | 所有请求和错误，可展开看完整 JSON，可导出 |

资源列表**按 Free 剩余时间从多到少排序**（缺截止时间的排最后）。
每行的按钮会根据下载器状态显示「一键下载」「下载中」或「已下载」；
被本地准入拦下时显示「准入拦截」，悬停能看到具体原因。

顶部「一键下载推荐」会把当前所有推荐资源逐个提交，每个都单独走一遍准入。

### 它还会告诉你

- **账号概况**：分享率、上传量、下载量、当前魔力、每小时魔力、做种数和做种体积
- **新手考核卡**：上传/下载/魔力三项缺口、截止底线、提前 5 天的安全目标、当前安全余量
- **回填 Free 截止**：qB 里原先手动添加、仍在下载的 M-Team 任务，按名称和字节体积**精确匹配**后补写截止标签，补上后才受 Free 保护。已完成和做种中的任务不会被改动

### 限制

- Chrome 关掉就不工作，Service Worker 也可能被系统休眠
- 种子文件受同源策略限制：M-Team 的下载地址会 302 到 CDN，拿不到字节时会退化成把 URL 交给下载器自己抓，成功率低一些
- Free 到期自动删除**默认关闭**，要在「设置 → Free 到期保护」里显式打开

详见 [pt-agent-extension/README.md](pt-agent-extension/README.md)。

## 二、终端守护进程

跑在常开机器上的无人值守版。**这是推荐用法**——Free 是有时限的，人不可能 24 小时盯着。

### 安装

需要 Node.js 20+，零第三方依赖。

```bash
cd pt-agent-daemon
./install.sh
```

脚本会检查 Node 版本、校验决策引擎完整性、建数据目录、准备 `.env`、
装一个 `ptagent` 命令，最后跑一次体检。**全程不写任何密钥、不覆盖已有配置**。

### 配置

全部配置装在一个 `.env` 里，拷到另一台机器就能直接跑：

```bash
# 站点
PTAGENT_SITE_API_KEY=你的APIKEY

# 下载器（可多台，顺序即探测优先级，内网放前面）
PTAGENT_DOWNLOADER_1_NAME=内网qB
PTAGENT_DOWNLOADER_1_ADDRESS=http://192.168.1.10:8080/
PTAGENT_DOWNLOADER_1_USERNAME=admin
PTAGENT_DOWNLOADER_1_PASSWORD=你的密码

PTAGENT_DOWNLOADER_2_NAME=公网qB
PTAGENT_DOWNLOADER_2_ADDRESS=https://qb.example.com/

# 扫描节奏：40 到 90 分钟之间随机
PTAGENT_SCAN_MIN_MINUTES=40
PTAGENT_SCAN_MAX_MINUTES=90
PTAGENT_MAX_PUSH_PER_SCAN=5
```

完整模板见 [`.env.example`](pt-agent-daemon/.env.example)，也可以用 CLI 或 WebUI 改。

**为什么是随机间隔**：固定周期在站点侧是很明显的机器人特征，随机化同时也能错开抢种高峰。
两个值填成一样就退化为固定周期。

### 跑起来

```bash
ptagent doctor              # 体检：配置、决策引擎、站点与下载器连通性
ptagent scan --dry-run      # 空跑一轮，只评估不下载 —— 建议先这么看两三轮
ptagent start               # 前台启动
```

装成开机自启的后台服务：

```bash
./scripts/service.sh install     # Linux 用 systemd，macOS 用 launchd
./scripts/service.sh status
./scripts/service.sh logs
```

或者用 Docker（群晖推荐）：

```bash
export PTAGENT_WEB_TOKEN=$(openssl rand -hex 16)
docker compose up -d
```

### 命令

**一次性动作**

| 命令 | 说明 |
|---|---|
| `ptagent scan [--dry-run]` | 立刻扫描一轮 |
| `ptagent guard [--dry-run]` | 立刻跑一次 Free 到期保护 |
| `ptagent backfill` | 给下载器里缺 Free 截止标签的任务回查补上 |
| `ptagent push <种子ID...>` | 手动推送指定资源 |

**查看**

| 命令 | 说明 |
|---|---|
| `ptagent status` | 下次扫描时间、上一轮结果 |
| `ptagent resources [--filter recommend]` | 最近一次扫描的评估明细 |
| `ptagent tasks` | 下载器当前任务与保护状态 |
| `ptagent logs [--level error] [--prefix push:]` | 运行日志 |
| `ptagent audit` | 生命周期审计：什么被加了、什么被删了 |

**配置**

| 命令 | 说明 |
|---|---|
| `ptagent config list` / `set <键> <值>` | 查看 / 修改 |
| `ptagent config export-env [文件]` | 导出成 `.env`，用于搬到另一台机器 |
| `ptagent import <插件导出的.json>` | 从 Chrome 插件整体导入配置 |
| `ptagent downloader list\|add\|test` | |
| `ptagent site list\|add` | |

所有命令都支持 `--json`，日志和审计是 JSONL 逐行可解析——方便脚本或 AI agent 直接消费，
见 [AGENTS.md](pt-agent-daemon/AGENTS.md)。

### WebUI

默认 `http://127.0.0.1:7788/`，视觉和插件一致。五个视图：运行总览、种子决策、下载中、设置、日志。

要从别的机器访问必须同时设访问令牌，否则**拒绝启动**——配置文件里有下载器密码和站点 API Key：

```bash
ptagent config set webHost 0.0.0.0
ptagent config set webToken $(openssl rand -hex 16)
```

页面上永远看不到密码和 API Key，接口出站前一律脱敏，只回一个「填过没有」的标记。

详见 [pt-agent-daemon/README.md](pt-agent-daemon/README.md) 和
[部署指南 DEPLOY.md](pt-agent-daemon/DEPLOY.md)。

## 两个版本的关系

### 决策逻辑只有一份

评分、决策、准入、Free 保护、qBittorrent 客户端这 12 个模块的**源头在 `pt-agent-extension/`**，
守护进程以**逐字节副本**的形式带在 `pt-agent-daemon/vendor/engines/`。

有两份副本，最大的风险是它们悄悄跑偏——插件改了评分，终端版还按老规则跑，而且没人发现。
所以 `MANIFEST.json` 记录每个文件的 sha256，两层校验都由测试兜底：

| 校验 | 抓什么 | 什么时候能跑 |
|---|---|---|
| 副本 vs MANIFEST | vendor 目录被手工改过 | 任何时候，包括单独发布的副本 |
| 副本 vs 插件源文件 | 插件改了但忘了同步 | 只在完整仓库里 |

**要改判定规则，改 `pt-agent-extension/` 里的源文件，然后 `npm run sync-engines`。**
这样守护进程能单独打包发到 NAS 上，同时不会出现「插件说推荐、终端说拒绝」这种没法解释的分歧。

### 配置可以互相搬

插件：**设置 → 配置迁移 → 导出配置 JSON**，然后：

```bash
ptagent import pt-agent-config-xxx.json
ptagent config export-env .env      # 再生成一个能拷到别的机器的文件
```

## 它怎么决定下载什么

一个资源要真正被推送，必须连过两关。

**第一关，决策引擎**（扫描时逐个判定）：

- 不是明确 Free / 2xFree → 拒绝
- Free 已到期 → 拒绝
- HR 任务 → 拒绝（可配）
- 0 做种 → 风险
- 下载人数不高于做种人数 → 不进入推荐
- 进入保护窗口（默认到期前 10 分钟）→ 风险

通过的资源按 2xFree、Free 剩余时长、做种供给、供需比、体积算分，满分 100。

对 **1–2 个做种但下载需求极高**的稀缺资源有额外的机会模型：
Free 至少 6 小时、下载人数至少 20、下载/做种比至少 10、完成所需均速不超过 512 KiB/s
时允许推荐——能不能下完由「所需均速」判断，比拍一个固定 GB 上限更准。

**第二关，本地安全准入**（入队瞬间）：

| 参数 | 默认值 | 说明 |
|---|---|---|
| 最低评分 | 80 | |
| 单任务体积上限 | 50 GB | |
| Free 最短剩余 | 12 小时 | 稀缺高需求资源可豁免 |
| 最低分享率 | 1.0 | 填 0 表示不检查 |
| 并发提醒阈值 | 3 | **仅提示不拦截** |

分成两步是因为并发数、分享率这类条件会随时变化，只能在入队瞬间判断。

**并发数只提示不拦截**——下载器自己有队列，超出上限的任务会排队而不是丢失。
统计并发时只计入真正占用下载槽的任务，暂停和排队中的不算。

守护进程的推送优先级是 **Free 剩余时间从多到少**：剩余越长越有把握在 Free 结束前下完，
快到期的即使评分高也很可能被保护机制删掉，先推它是浪费带宽。

## Free 到期保护

入队时会给任务打两个标签：

- `ptagent` —— 标记「这是本工具加的」
- `ptagent-free-end=<ISO 时间>` —— Free 截止时间

保护检查定期回读这些标签，在**到期前 `guardMinutes` 分钟**（默认 10）
把还没下完的任务连文件一起删掉。

已经在下载器里但缺截止标签的老任务，用回填功能补上——补上后它们才受保护。

## 现状与限制

- **站点**：只实现了 M-Team（API 模式）。站点适配层已按多站点设计，接新站点补一个适配器即可
- **下载器**：只实现了 qBittorrent。Transmission / Deluge 的适配层位置已留好，`implemented` 打开即可接入
- **测试**：插件 177 个，守护进程 100 个。核心链路用一个同时扮演 M-Team 和 qBittorrent 的假网络跑完整流程，不是只测单个函数

## 安全

这个工具**会删文件**。几条边界写死在代码里并有测试守着：

- 只删带 `ptagent` 标签的任务（本工具自己加的）
- **已完成的任务不删**——还要留着做种
- 打了 `pt_agent_keep` / `pt_agent_nodel` 保护标签的不删
- 关掉自动删除时只告警不动手

所有删除动作都记进审计日志。要复盘「我的文件为什么没了」，查
`action: guard_delete` 且 `deleteFiles: true` 的记录即可。

**凭据处理**：

- 插件的 `private-config.js`、守护进程的 `.env` 都在 `.gitignore` 里，导出的 `.env` 权限 600
- WebUI 所有接口出站前脱敏密码、API Key 和访问令牌，只回 `hasPassword` 这类标记
- WebUI 绑非回环地址时强制要求访问令牌，不设就拒绝启动
- 连续认证失败会触发退避（qB 封 IP 后继续重试只会把封禁窗口无限续期）

## 开发

```bash
# 插件
cd pt-agent-extension && node --test

# 守护进程
cd pt-agent-daemon && npm test
npm run check-engines        # 校验 vendor 副本与插件源文件一致
npm run sync-engines         # 改完插件的判定逻辑后同步
```

两边都是零第三方依赖，只用 Node 内置的 `node:test`。
